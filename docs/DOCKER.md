# Инструкция по использованию Docker

## Что такое Docker?

Docker — это платформа для контейнеризации приложений, которая позволяет упаковать приложение со всеми его зависимостями в изолированный контейнер. Контейнер работает одинаково на любой системе, где установлен Docker, что решает проблему "работает на моей машине".

### Основные концепции Docker

#### Образ (Image)
**Образ** — это шаблон для создания контейнеров. Это неизменяемый файл, содержащий код приложения, зависимости, библиотеки и конфигурацию. В этом проекте образ создается из `Dockerfile` и включает:
- Базовый образ Node.js 18 на Alpine Linux
- Установленный Chromium браузер
- Скомпилированный TypeScript код
- Установленные npm зависимости

#### Контейнер (Container)
**Контейнер** — это запущенный экземпляр образа. Это изолированная среда выполнения, которая:
- Имеет собственную файловую систему
- Изолирована от других контейнеров и хоста
- Использует ресурсы хоста (CPU, память, сеть)
- Может быть остановлена, перезапущена или удалена

#### Dockerfile
**Dockerfile** — это инструкция для сборки образа. В этом проекте `Dockerfile`:
1. Использует базовый образ `node:18-alpine` (легковесный Linux)
2. Устанавливает Chromium и необходимые библиотеки для работы браузера
3. Копирует файлы проекта и устанавливает зависимости
4. Компилирует TypeScript код
5. Устанавливает команду запуска приложения

#### Docker Compose
**Docker Compose** — инструмент для управления многоконтейнерными приложениями через файл `docker-compose.yml`. Позволяет:
- Определить все сервисы в одном файле
- Настроить переменные окружения
- Настроить volumes (монтирование папок)
- Управлять несколькими контейнерами одной командой

### Зачем использовать Docker для этого проекта?

1. **Изоляция зависимостей**: Chromium и Node.js устанавливаются внутри контейнера, не засоряя систему
2. **Кроссплатформенность**: Работает одинаково на Windows, Linux и macOS
3. **Простота развертывания**: Не нужно вручную устанавливать Chromium и настраивать пути
4. **Автоматический перезапуск**: Контейнер автоматически перезапускается при сбое
5. **Управление версиями**: Можно легко переключаться между версиями приложения

### Жизненный цикл контейнера

1. **Сборка образа** (`docker-compose build`):
   - Читает `Dockerfile`
   - Скачивает базовый образ Node.js
   - Устанавливает Chromium и зависимости
   - Копирует код и компилирует TypeScript
   - Создает образ `twitch_watcher`

2. **Запуск контейнера** (`docker-compose up`):
   - Создает контейнер из образа
   - Применяет переменные окружения из `docker-compose.yml`
   - Монтирует volume для скриншотов
   - Запускает команду `npm start`

3. **Работа контейнера**:
   - Приложение работает внутри контейнера
   - Скриншоты сохраняются в `./screenshots` на хосте
   - Логи выводятся через `docker-compose logs`

4. **Остановка** (`docker-compose down`):
   - Останавливает контейнер
   - Удаляет контейнер (но не образ)
   - Volumes остаются (скриншоты сохраняются)

## Разбор конфигурационных файлов

### Dockerfile - пошаговое объяснение

Давайте разберем `Dockerfile` построчно:

```dockerfile
FROM node:18-alpine
```
Использует официальный образ Node.js версии 18 на базе Alpine Linux. Alpine — это минималистичный Linux дистрибутив (~5MB), что делает образ легковесным.

```dockerfile
RUN apk add --no-cache \
    chromium \
    nss \
    freetype \
    ...
```
Устанавливает Chromium и необходимые библиотеки через пакетный менеджер Alpine (`apk`):
- `chromium` — браузер для автоматизации
- `nss`, `freetype`, `harfbuzz` — библиотеки для рендеринга шрифтов и графики
- `ca-certificates` — сертификаты для HTTPS соединений
- `ttf-freefont` — шрифты для отображения текста

Флаг `--no-cache` предотвращает сохранение кэша пакетов, уменьшая размер образа.

```dockerfile
ENV PUPPETEER_SKIP_CHROMIUM_DOWNLOAD=true \
    PUPPETEER_EXECUTABLE_PATH=/usr/bin/chromium-browser
```
Переменные окружения для Puppeteer:
- `PUPPETEER_SKIP_CHROMIUM_DOWNLOAD` — не скачивать Chromium (используем установленный)
- `PUPPETEER_EXECUTABLE_PATH` — путь к исполняемому файлу браузера

```dockerfile
WORKDIR /usr/src/app
```
Устанавливает рабочую директорию внутри контейнера. Все последующие команды выполняются в этой папке.

```dockerfile
COPY package*.json ./
COPY tsconfig.json ./
RUN npm install
```
Копирует файлы зависимостей и устанавливает npm пакеты. Это делается отдельно от кода, чтобы использовать кэш Docker при изменении только исходного кода.

```dockerfile
COPY src ./src
RUN npm run build
```
Копирует исходный код и компилирует TypeScript в JavaScript.

```dockerfile
CMD ["npm","start"]
```
Команда, которая выполняется при запуске контейнера. Запускает скомпилированное приложение.

### docker-compose.yml - структура и параметры

```yaml
version: '3.5'
```
Версия формата Docker Compose. Версия 3.5 поддерживает все современные функции.

```yaml
services:
  twitch_watcher:
```
Определяет сервис с именем `twitch_watcher`. В Docker Compose может быть несколько сервисов.

```yaml
build: .
```
Указывает, что образ нужно собрать из `Dockerfile` в текущей директории (`.`).

```yaml
restart: always
```
Политика перезапуска:
- `always` — всегда перезапускать контейнер при остановке (включая ручную остановку)
- `unless-stopped` — перезапускать, если не остановлен вручную
- `on-failure` — перезапускать только при ошибке
- `no` — не перезапускать автоматически

```yaml
env_file:
  - .env
```
Загружает переменные окружения из файла `.env`. Это безопасный способ хранения секретных данных (токенов, паролей), так как `.env` файл не попадает в репозиторий.

```yaml
environment:
  - token=${token}
  - channelsWithPriority=${channelsWithPriority}
  - MODE=${MODE:-api}
```
Переменные окружения, доступные внутри контейнера. Значения берутся из `.env` файла или имеют значения по умолчанию (например, `MODE:-api` означает, что если `MODE` не указан, будет использоваться `api`).

```yaml
volumes:
  - "./screenshots:/usr/src/app/screenshots"
```
Монтирование папок (volumes):
- `./screenshots` — папка на хосте (вашем компьютере)
- `:/usr/src/app/screenshots` — папка внутри контейнера
- Двоеточие разделяет путь хоста и путь контейнера

Это позволяет сохранять скриншоты на вашем компьютере, даже если контейнер будет удален.

### Слои Docker образа

Docker использует слоистую файловую систему (Union File System). Каждая команда в Dockerfile создает новый слой:

```
Слой 1: FROM node:18-alpine          (базовый образ)
Слой 2: RUN apk add chromium         (установка Chromium)
Слой 3: COPY package*.json           (копирование зависимостей)
Слой 4: RUN npm install              (установка npm пакетов)
Слой 5: COPY src                     (копирование кода)
Слой 6: RUN npm run build            (компиляция)
Слой 7: CMD ["npm","start"]          (команда запуска)
```

Преимущества слоев:
- **Кэширование**: Если не изменились зависимости, Docker использует кэшированный слой
- **Эффективность**: При изменении только кода не нужно переустанавливать зависимости
- **Размер**: Общие слои между образами хранятся один раз

## Быстрый старт

### 1. Настройка конфигурации

Создайте файл `.env` на основе примера:

```bash
# Windows (PowerShell)
Copy-Item .env.example .env

# Linux/macOS
cp .env.example .env
```

### 2. Редактирование .env файла

Откройте `.env` и настройте обязательные параметры:

```env
# ОБЯЗАТЕЛЬНО: Замените на ваш токен Twitch
token=your_auth_token_here

# ОБЯЗАТЕЛЬНО: Укажите список приоритетных стримеров
channelsWithPriority=alkaizerx,mathil1

# Режим работы: api или puppeteer (по умолчанию puppeteer)
MODE=api

# Параметры просмотра (в минутах) - только для puppeteer режима
minWatching=15
maxWatching=30

# Параметры скриншотов - только для puppeteer режима
browserScreenshot=false
screenshotInterval=0
```

**Важно:** Файл `.env` содержит секретные данные (токен) и не должен попадать в репозиторий. Он уже добавлен в `.gitignore`.

### 3. Запуск контейнера

```bash
# Сборка и запуск в фоновом режиме
docker-compose up -d

# Просмотр логов
docker-compose logs -f

# Просмотр логов конкретного сервиса
docker-compose logs -f twitch_watcher
```

### 4. Остановка контейнера

```bash
# Остановка контейнера
docker-compose stop

# Остановка и удаление контейнера
docker-compose down
```

## Обновление конфигурации

После изменения `docker-compose.yml` нужно применить изменения:

### Способ 1: Перезапуск с новой конфигурацией (рекомендуется)

```bash
# Остановка и удаление старых контейнеров
docker-compose down

# Запуск с новой конфигурацией
docker-compose up -d

# Просмотр логов для проверки
docker-compose logs -f
```

### Способ 2: Перезапуск без остановки (быстрее)

```bash
# Перезапуск контейнера (применяет новые переменные окружения)
docker-compose up -d --force-recreate

# Или просто перезапуск
docker-compose restart
```

### Способ 3: Если изменился Dockerfile

Если вы изменили `Dockerfile`, нужно пересобрать образ:

```bash
# Пересборка образа и перезапуск
docker-compose up -d --build

# Или с полной пересборкой без кэша
docker-compose build --no-cache
docker-compose up -d
```

### Что происходит при обновлении:

- **Переменные окружения** - применяются автоматически при перезапуске
- **Volumes** - остаются без изменений (скриншоты сохраняются)
- **Порты** - применяются новые настройки портов (если были изменены)
- **Dockerfile** - требует пересборки образа (`--build`)

### Проверка применения изменений

```bash
# Проверить текущие переменные окружения контейнера
docker-compose exec twitch_watcher env | grep -E "token|channelsWithPriority|minWatching"

# Или посмотреть конфигурацию
docker-compose config
```

## Скриншоты

Скриншоты сохраняются в папку `./screenshots` на хосте (монтируется как volume).

## Переменные окружения

Все переменные окружения настраиваются в файле `.env`. Создайте его на основе `.env.example`:

```bash
# Windows (PowerShell)
Copy-Item .env.example .env

# Linux/macOS
cp .env.example .env
```

### Обязательные параметры:

- `token` - Токен авторизации Twitch (обязательно)
- `channelsWithPriority` - Список приоритетных стримеров через запятую (обязательно)

### Параметры просмотра:

- `minWatching` - Минимальное время просмотра (в минутах, по умолчанию 15)
- `maxWatching` - Максимальное время просмотра (в минутах, по умолчанию 30)

### Параметры скриншотов:

- `browserScreenshot` - Включить/выключить скриншоты (true/false, 1/0, yes/no)
- `screenshotInterval` - Интервал для периодических скриншотов (в секундах, 0 = отключено)

### Параметры браузера:

- `exec` - Путь к исполняемому файлу браузера (для Docker: `/usr/bin/chromium-browser`)
- `userAgent` - User-Agent браузера (опционально)
- `timeout` - Таймаут для операций (в миллисекундах, 0 = без таймаута)

### Параметры прокси (опционально):

- `proxy` - Прокси сервер (формат: ip:port)
- `proxyAuth` - Авторизация прокси (формат: username:password)

## Как Docker работает с ресурсами

### Изоляция процессов

Каждый контейнер имеет:
- **Собственное пространство процессов** — процессы внутри контейнера изолированы
- **Собственную файловую систему** — изменения в контейнере не влияют на хост
- **Собственную сеть** — контейнеры могут общаться через внутреннюю сеть Docker

### Использование памяти и CPU

Docker контейнеры используют ресурсы хоста, но могут быть ограничены:

```yaml
# Пример ограничений в docker-compose.yml (не используется в текущем проекте)
services:
  twitch_watcher:
    deploy:
      resources:
        limits:
          cpus: '1.0'      # Максимум 1 CPU
          memory: 512M     # Максимум 512 MB памяти
        reservations:
          cpus: '0.5'      # Минимум 0.5 CPU
          memory: 256M     # Минимум 256 MB памяти
```

В текущем проекте ограничения не установлены, контейнер использует доступные ресурсы хоста.

### Сетевая изоляция

Docker создает виртуальную сеть для контейнеров:
- Контейнеры могут общаться друг с другом по именам сервисов
- По умолчанию контейнеры не доступны извне (если не проброшены порты)
- В этом проекте сетевые порты не используются, так как приложение работает локально

### Персистентность данных

Данные в контейнере по умолчанию **не сохраняются** при удалении контейнера. Для сохранения используются:

1. **Volumes** (используется в проекте):
   ```yaml
   volumes:
     - "./screenshots:/usr/src/app/screenshots"
   ```
   Папка монтируется с хоста, данные сохраняются навсегда.

2. **Named volumes**:
   ```yaml
   volumes:
     - screenshots_data:/usr/src/app/screenshots
   volumes:
     screenshots_data:
   ```
   Docker управляет местом хранения, данные сохраняются между перезапусками.

3. **Bind mounts** (текущий вариант):
   Прямое монтирование папки хоста в контейнер. Проще для разработки.

## Решение проблем

### Контейнер не запускается

1. Проверьте логи: `docker-compose logs`
2. Убедитесь, что токен указан правильно
3. Проверьте, что указаны приоритетные стримеры

### Браузер не запускается

1. Убедитесь, что путь к Chromium правильный: `/usr/bin/chromium-browser`
2. Проверьте логи на ошибки запуска браузера

### Скриншоты не сохраняются

1. Проверьте права доступа к папке `./screenshots`
2. Убедитесь, что volume правильно смонтирован
3. Проверьте, что `browserScreenshot=true`

## Автоматический перезапуск

Контейнер настроен на автоматический перезапуск при сбое (`restart: always`).

## Мониторинг

Для мониторинга работы контейнера используйте:

```bash
# Логи в реальном времени
docker-compose logs -f twitch_watcher

# Статистика ресурсов
docker stats twitch_watcher

# Статистика ресурсов в компактном виде
docker stats --no-stream twitch_watcher
```

### Что мониторить

1. **Использование памяти**: Chromium может потреблять много памяти. Если контейнер падает, проверьте логи на ошибки нехватки памяти.
2. **Использование CPU**: Высокая нагрузка может быть нормальной при работе браузера.
3. **Логи**: Регулярно проверяйте логи на ошибки авторизации или проблемы с браузером.

## Лучшие практики

### Безопасность

1. **Не коммитьте токены в git**: Используйте `docker-compose-example.yml` как шаблон, а реальные токены храните в `docker-compose.yml`, который добавлен в `.gitignore`.

2. **Ограничение ресурсов**: Для продакшена рекомендуется установить лимиты памяти и CPU, чтобы контейнер не мог исчерпать ресурсы хоста.

3. **Обновление образов**: Регулярно обновляйте базовый образ `node:18-alpine` для получения обновлений безопасности:
   ```bash
   docker-compose build --pull
   ```

### Производительность

1. **Кэширование слоев**: Порядок команд в Dockerfile оптимизирован для кэширования:
   - Сначала копируются зависимости (`package.json`)
   - Затем устанавливаются пакеты
   - В конце копируется код
   
   Это позволяет не переустанавливать зависимости при изменении только кода.

2. **Многоэтапная сборка**: Для продакшена можно использовать multi-stage build для уменьшения размера образа:
   ```dockerfile
   # Этап сборки
   FROM node:18-alpine AS builder
   WORKDIR /app
   COPY package*.json ./
   RUN npm install
   COPY . .
   RUN npm run build
   
   # Этап запуска
   FROM node:18-alpine
   RUN apk add --no-cache chromium ...
   WORKDIR /usr/src/app
   COPY --from=builder /app/dist ./dist
   COPY package*.json ./
   RUN npm install --production
   CMD ["npm","start"]
   ```

### Управление версиями

1. **Тегирование образов**: Для продакшена используйте теги версий:
   ```bash
   docker build -t twitch-watcher:v2.0.5 .
   docker-compose build --tag twitch-watcher:latest
   ```

2. **Резервное копирование**: Регулярно делайте резервные копии папки `screenshots` и `docker-compose.yml`.

## Типичные сценарии использования

### Разработка

При разработке удобно использовать Docker для тестирования окружения:

```bash
# Запуск в интерактивном режиме с просмотром логов
docker-compose up

# Пересборка после изменений в коде
docker-compose up -d --build

# Вход в контейнер для отладки
docker-compose exec twitch_watcher sh
```

### Продакшен

Для продакшена рекомендуется:

1. Использовать named volumes вместо bind mounts:
   ```yaml
   volumes:
     - screenshots_data:/usr/src/app/screenshots
   volumes:
     screenshots_data:
   ```

2. Настроить автоматический перезапуск через systemd или другой процесс-менеджер:
   ```ini
   [Unit]
   Description=Twitch Watcher Docker Compose
   Requires=docker.service
   After=docker.service
   
   [Service]
   Type=oneshot
   RemainAfterExit=yes
   WorkingDirectory=/path/to/twitch_watcher
   ExecStart=/usr/local/bin/docker-compose up -d
   ExecStop=/usr/local/bin/docker-compose down
   TimeoutStartSec=0
   
   [Install]
   WantedBy=multi-user.target
   ```

3. Настроить ротацию логов:
   ```yaml
   logging:
     driver: "json-file"
     options:
       max-size: "10m"
       max-file: "3"
   ```

### Обновление приложения

Процесс обновления:

```bash
# 1. Остановить текущий контейнер
docker-compose down

# 2. Обновить код (git pull или копирование файлов)

# 3. Пересобрать образ
docker-compose build --no-cache

# 4. Запустить новый контейнер
docker-compose up -d

# 5. Проверить логи
docker-compose logs -f
```

### Откат к предыдущей версии

Если новая версия работает некорректно:

```bash
# 1. Остановить текущий контейнер
docker-compose down

# 2. Вернуться к предыдущей версии кода (git checkout)

# 3. Пересобрать образ
docker-compose build

# 4. Запустить контейнер
docker-compose up -d
```

## Часто задаваемые вопросы

### Почему контейнер занимает много места на диске?

Docker хранит образы и контейнеры на диске. Для очистки:
```bash
docker system prune -a
```

### Можно ли запустить несколько экземпляров приложения?

Да, можно запустить несколько контейнеров с разными конфигурациями:
```bash
# Используйте разные имена проектов
docker-compose -p twitch_watcher_1 -f docker-compose.yml up -d
docker-compose -p twitch_watcher_2 -f docker-compose.yml up -d
```

### Как обновить только зависимости без пересборки всего образа?

Измените `package.json`, затем:
```bash
docker-compose build --no-cache
```

### Почему скриншоты не сохраняются?

Проверьте:
1. Существует ли папка `./screenshots` на хосте
2. Правильно ли настроен volume в `docker-compose.yml`
3. Права доступа к папке (на Linux может потребоваться `chmod`)

### Как посмотреть, что происходит внутри контейнера?

```bash
# Вход в контейнер
docker-compose exec twitch_watcher sh

# Просмотр файлов
docker-compose exec twitch_watcher ls -la

# Просмотр переменных окружения
docker-compose exec twitch_watcher env

# Просмотр процессов
docker-compose exec twitch_watcher ps aux
```
