# Анализ проблемы: баллы не начисляются при отправке событий просмотра

## Проблема

События просмотра (`minute-watched`) успешно отправляются в Twitch, но баллы канала не изменяются, так как события о начислении баллов (`points-earned`) не приходят через WebSocket.

## Архитектура системы

### 1. Отправка событий просмотра
- **Метод**: `TwitchAPI.sendMinuteWatched()`
- **Частота**: Каждую минуту для каждого онлайн стримера
- **Эндпоинт**: `spade_url` стримера (получается через GraphQL)
- **Статус**: ✅ Работает (в логах видно "Minute watched event sent")

### 2. Получение событий о начислении баллов
- **Метод**: WebSocket PubSub топик `community-points-user-v1.{userId}`
- **Обработчик**: `WebSocketManager.handleCommunityPointsMessage()`
- **Событие**: `points-earned` с данными о балансе и заработанных баллах
- **Статус**: ❌ Не работает (WebSocket не инициализирован)

## Корневая причина

### Проблема #1: Невалидный токен
```
❌ Token validation failed - token is invalid
❌ Failed to initialize WebSocket: Token is invalid or user_id not found in token validation
⚠️ Continuing without WebSocket - events will be sent via API only
```

**Последствия:**
- WebSocket не может инициализироваться (строка 196-200 в `StreamWatcher.ts`)
- Подписка на топик `community-points-user-v1.{userId}` не происходит
- События `points-earned` не приходят от Twitch
- Баллы не обновляются, даже если события просмотра отправляются

### Проблема #2: Сетевые ошибки
```
❌ Сетевая ошибка при подключении к api.twitch.tv
❌ Сетевая ошибка при подключении к gql.twitch.tv
❌ Circuit Breaker OPEN для GraphQL запросов
```

**Что это означает:**

1. **Сетевые ошибки** (`fetch failed`, `ECONNREFUSED`, `ENOTFOUND`, `EAI_AGAIN`):
   - Приложение не может установить соединение с серверами Twitch
   - Возможные причины:
     - Проблемы с DNS (не удается разрешить доменные имена)
     - Проблемы с интернет-соединением
     - Блокировка доступа к Twitch (прокси, файрвол, VPN)
     - Таймауты соединения
     - Перегрузка сети

2. **Circuit Breaker OPEN**:
   - Это защитный механизм приложения, который блокирует запросы при множественных ошибках
   - **Как работает:**
     - После 5 последовательных ошибок (по умолчанию) Circuit Breaker переходит в состояние `OPEN`
     - В этом состоянии все запросы блокируются без попытки выполнения
     - Через 30 секунд (по умолчанию) Circuit Breaker переходит в состояние `HALF_OPEN` для тестирования
     - Если тестовый запрос успешен, Circuit Breaker переходит в `CLOSED` (нормальная работа)
     - Если тестовый запрос неудачен, Circuit Breaker снова переходит в `OPEN`

**Последствия:**
- Проблемы с получением `spade_url` через GraphQL
- Проблемы с валидацией токена
- Проблемы с получением информации о каналах
- Все GraphQL запросы блокируются, пока Circuit Breaker не восстановится
- Приложение продолжает работать, но не может обновлять данные через API

## Почему события просмотра отправляются, но баллы не начисляются?

1. **События просмотра отправляются напрямую** на `spade_url` стримера через HTTP POST запрос. Это не требует WebSocket соединения.

2. **События о начислении баллов приходят через WebSocket** в топик `community-points-user-v1.{userId}`. Без активного WebSocket соединения эти события не могут быть получены.

3. **Приложение продолжает работать без WebSocket** (graceful degradation), отправляя события просмотра, но не получая уведомления о начислении баллов.

## Автоматическое восстановление

Приложение теперь автоматически пытается переинициализировать WebSocket, если он не был инициализирован при старте:

1. **Первая попытка**: Через 30 секунд после неудачной инициализации
2. **Повторные попытки**: Каждые 5 минут, если WebSocket не инициализирован
3. **Периодическая проверка**: Каждые 5 минут проверяется статус WebSocket и выполняется переинициализация при необходимости

В логах вы увидите:
```
⚠️  Attempting to reinitialize WebSocket connection...
✅  WebSocket reinitialized successfully
```

## Решение

### Шаг 1: Проверить и обновить токен
1. Убедитесь, что токен в `config.json` или `.env` файле валидный
2. Проверьте, что токен имеет необходимые scope:
   - `channel:read:redemptions` (для баллов канала)
   - `user:read:email` (опционально)
3. Обновите токен, если он истек или невалидный

### Шаг 2: Проверить сетевые настройки
1. **DNS:** убедитесь, что резолвятся `id.twitch.tv` и `gql.twitch.tv` (при необходимости укажите публичные DNS в системе или роутере).

2. **Проверка доступности Twitch API:**
   ```bash
   curl https://id.twitch.tv/oauth2/validate
   curl https://gql.twitch.tv/gql
   ```

3. **Проверка прокси/файрвола:**
   - Убедитесь, что хост имеет доступ к интернету
   - При необходимости настройте `proxy` в «Конфиг бота»
   - Проверьте, что порты не заблокированы

### Шаг 3: Проверить логи инициализации WebSocket
Ищите в логах:
- ✅ `WebSocket initialized successfully` - WebSocket работает
- ❌ `Failed to initialize WebSocket` - WebSocket не работает
- ❌ `Token validation failed` - проблема с токеном
- ❌ `DNS ошибка` - проблема с сетью

### Шаг 4: Проверить подписку на топик
После успешной инициализации WebSocket должны быть логи:
```
📡 Subscribing to community-points-user-v1.{userId} for user {userId}
✅ WebSocket subscription successful
```

Если этих логов нет, подписка не произошла.

## Диагностика

### Проверка статуса WebSocket
Используйте health check endpoint:
```bash
curl http://localhost:3000/health
```

Проверьте секцию `websocket`:
- `status: "healthy"` - WebSocket подключен и работает
- `status: "unhealthy"` - WebSocket не подключен (приложение пытается переподключиться)
- `status: "unknown"` - WebSocket менеджер не инициализирован (приложение пытается инициализировать)

**Важно**: Если статус `unknown` или `unhealthy`, приложение автоматически пытается восстановить соединение. Проверьте логи для получения дополнительной информации.

### Проверка получения событий
В логах должны быть сообщения:
```
💰 WebSocket: points-earned event - balance=XXX, earned=YYY, reason=WATCH
🚀 +YYY → {username} - Reason: WATCH
📊 [{username}] Balance updated: OLD → NEW (earned: YYY, reason: WATCH)
```

Если этих сообщений нет, события не приходят через WebSocket.

## Альтернативные способы получения баллов

Если WebSocket не работает, приложение может периодически запрашивать баланс через GraphQL:
- Метод: `GraphQLClient.getChannelPoints()`
- Частота: При обновлении информации о стримере
- Ограничение: Не в реальном времени, только при обновлении

Однако это не заменяет WebSocket для получения событий в реальном времени.

## Рекомендации

1. **Всегда проверяйте статус WebSocket** при запуске приложения
2. **Мониторьте логи** на наличие ошибок валидации токена
3. **Настройте автоматическое обновление токена** перед истечением
4. **Используйте health check endpoint** для мониторинга состояния
5. **Проверяйте сетевые настройки** при проблемах с подключением
